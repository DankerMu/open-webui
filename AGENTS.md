## Code Canonicality

Same logic must have exactly one implementation in the repo. Version evolution belongs in git history, not in filenames or identifiers.

- Before adding any function, class, module, or file: grep the codebase for existing similar implementations. If found, extend or refactor the existing one. Only create new if truly absent.
- Forbidden suffixes for filenames, class names, function names, and module names: `_v1`, `_v2`, `_v3`, `_new`, `_old`, `_backup`, `_temp`, `_copy`, `_final`, `_real`, `_improved`, `_refactored`, `_fixed`, `_legacy`, `_deprecated`. If one exists in the codebase already, treat it as debt to unify, not a pattern to extend.
- Refactor in place: commit the working state first, modify the original file, run tests. If it breaks, `git revert`. Never keep an old version alongside the new "just in case" — git is the safety net.
- No parallel implementations as a transition. Replace atomically.
- Commented-out code is a lint error, not a safety net. Delete it; git remembers.
- Unreferenced exports and dead code paths are debt. Wire them up in the same change or delete them.
- Do not use the repo as a scratchpad. Directories like `tmp/`, `scratch/`, `backup/`, `_old/`, `deprecated/`, `archive/`, `wip/` must not appear in commits.

### Dependency policy

- **Lockfile**: `uv.lock` and `package-lock.json` committed. Agents run `make setup` after pulling and never bypass it; `uv sync --frozen`, `npm ci`.
- **Updates**: no Renovate/Dependabot configured on the fork. Upgrades require explicit confirmation (`## Agent Operating Rules`); a lockfile change must accompany its manifest change.
- **Pinning**: exact versions as upstream pins them; new dev tools pinned to a caret range in `package.json` / lower bound in `pyproject.toml`.
- **Forbidden**: `npm install <pkg>@latest`, `uv add` without confirmation, editing lockfiles by hand.
- **Misconfiguration fails loud**: an env toggle with an unexpected value throws instead of no-op; a missing file/key is an error, never a silent skip.

## Conventions

### Naming

- Files: `snake_case.py`, `kebab-case.ts`, `PascalCase.svelte` (upstream convention).
- Identifiers: `snake_case` (Python), `camelCase` (TS), `PascalCase` (classes/components).
- Tests: `backend/**/test_*.py`, `src/**/*.test.ts`, `e2e/*.spec.ts`.
- Forbidden suffixes: see Code Canonicality.

### Debt markers and deviations

- `FIXME` blocks the next release unless reviewers explicitly accept it; `TODO` fix when resources allow; `XXX` someday, no commitment.
- Every non-default configuration value carries an inline comment naming its motivating failure mode; an empty catch names what it swallows and why nothing else can reach it.

### Commit format

- Conventional commits required: `<type>(<scope>): <message>`; types `feat fix refactor chore docs test ci build perf`; scopes typically `ocu`, `office`, `webui`, `harness`, `docs`.
- Enforced by `.git-hooks/commit-msg` (pre-commit `commit-msg` stage). Agent commits add `Co-Authored-By`.

### Pull requests

- Use `.github/PULL_REQUEST_TEMPLATE.md`: Summary, Test plan, Runtime evidence, Risk, Canonicality check.
- Diff ≤ 400 lines excluding lockfiles/snapshots/i18n, or justified — review-only until the fork has CI.
- Docs change with code in the same PR: AGENTS.md, `docs/plans/`, decision record (`docs/decisions/`, note-required rule). Prose quality: `.omp/skills/prose-contract/SKILL.md`.
- Branch model: trunk-based on `main`; feature branches `<tool>/<short-slug>`; one task = one branch. `main` on the fork (`DankerMu/open-webui`) is protected: PR required, required check `All checks passed`, no force-push, no deletion, enforced for admins. Rewrite pushed feature-branch history only with `--force-with-lease`; no stacked-PR chains with manual retargeting.

### Coverage threshold

- Minimum 80% line coverage, **per file**, on files the fork adds (`make coverage-gate`). Files the fork modifies in upstream are reported advisory until `constraints.yaml baseline.counts.coverage_gap` reaches 0.
- Read an uncovered line as a dead-code candidate first and a missing test second. Never bolt an assertion-free test onto it.
- Every coverage exclusion carries a reason and an exit condition (`constraints.yaml exemptions`).

## Code Review Self-Check

- Can explain "why this approach" vs the nearest alternative; matched existing patterns unless there is a stated reason to diverge; fixed at the correct layer, not the symptom.
- Ran the checks selected per `### Scoped verification`; they pass on this branch. New/changed tests were red before the fix and green after.
- No canonicality violations (`_v2` files, duplicated logic, dead exports, scratch dirs); no hidden global state or undocumented environment-only behavior.
- Diff focused: no drive-by refactors of upstream files, no formatting churn. PR states intent, approach, test plan, risk, and what was not tested.

## Architecture Discipline

### Test-Driven Development

- Every new production file ships with a paired test file in the same change (`constraints.yaml testing.tdd_mode: required`); write the failing test first — a test that never went red proves nothing. `make coverage-gate` is the floor, not the definition of done.
- Mock dependencies, never the system under test. Backend route tests use FastAPI's `TestClient` against the harness DB; authorization tests assert the 401/403/404 matrix from `CONTEXT.md` invariants.

## Agent Operating Rules

### What agents may and may not do

- May: commit to feature branches `<tool>/<slug>`, open PRs to `main`, run every `make` target and the runtime harness locally, propose `AGENTS.md` changes (human acceptance before merge).
- May not: deploy to the LAN instance; force-push; use `--no-verify`; delete or rebuild any database other than `.run/data`; refactor upstream files the task does not touch (「顺手重构」); upgrade dependencies without explicit confirmation; add an Alembic migration not named in a plan; push to `main`; change CI files without flagging it in the PR.

### Skill / Memory boundaries

- Repo-local skills live in `.omp/skills/` (pre-push-checks, prose-contract, decision-record-lifecycle). **Readiness gap**: `.omp/` and `.claude/` are gitignored in this checkout, so these skills and `.claude/settings.json` are machine-local; a second machine must reinstall them.
- Per-session scratch files go to the session scratchpad or `/tmp/`, never the working tree. `.run/` is the only in-repo runtime directory and is gitignored.

### Debugging CI failures (protocol)

CI (`.github/workflows/ci.yml`) runs on the fork (`origin` = `DankerMu/open-webui`; `upstream` = `open-webui/open-webui`) and its `All checks passed` job is the required check on `main`. Classify the layer (`layer1-fast-checks`, `layer2-unit-tests`, `layer3-integration-tests`, `layer4-anti-drift`, `layer5-secret-scan`), read the first actionable error, reproduce locally with the same `make` target, fix the root cause, re-run that target, then `make check` before pushing. Environment-parity mismatches become a dated entry in `## Important Development Notes`.

### Evidence requirements

- Success claims require fresh command output from the current session: command + exit code + relevant output; without it a claim is unverified.
- **Verify the world, not the self-report.** Re-execute, re-read the file, hit the endpoint, query the row. Keyword-probing a transcript is not evidence. When a claim implies "nothing else changed", assert it.
- UI claims require a screenshot + zero new console errors. PRs include `## Runtime evidence`; "None — review-only change" only with a stated reason.

### Scoped verification — evidence matches the surface

Select the narrowest check that covers the changed behavior; report only commands actually run. Procedure: `.omp/skills/pre-push-checks/SKILL.md`.

| Change surface                    | Narrowest evidence                                              |
| --------------------------------- | --------------------------------------------------------------- |
| One backend module                | its `pytest` module + `make lint-scoped` + `make coverage-gate` |
| One frontend component            | `make test-frontend` + `make typecheck` + `make lint-scoped`    |
| Route / auth / socket / migration | the above + `make smoke` (+ `make db-verify` for migrations)    |
| UI-visible change                 | `make verify-ui`                                                |
| Docs / AGENTS.md / decisions      | `make doc-gate`, `make decisions-verify`                        |

- Never default to the full suite; never rerun a passing check just because a push comes next. Derive the change list via `bash scripts/change-scope.sh --status` — never from a guessed base. Name affected files explicitly for coverage; never hide an uncovered file behind `--passWithNoTests`.
- Iteration gates: max 3 fix-and-recheck cycles per failing check, then stop and report; never weaken, skip, or delete a test to get green (a skip needs a linked issue + deadline); checkpoint commit at every green state.

### Environment, concurrency, secrets

- Local: everything within these rules; `.run/data` is the only resettable database. LAN test/prod instances: no agent access — deployed by hand from the OCU deploy overlay.
- Parallel agents use separate git worktrees (`worktree-guard` hook enforces declared roots); rebase onto the target branch before opening or updating a PR; lockfile conflicts are resolved by re-running `uv sync` / `npm install` from the merged manifest, never by hand.
- Never read, cat, or print `.env` files or secret stores; `.env.example` is the only secrets-adjacent file agents may open (Claude Code denies `.env`, `.env.local`, `.env.production` explicitly). Reference secrets by variable name only; never paste values into PRs, commits, logs, or chat.

### Decision records, incidents, generated artifacts

- A non-trivial change ships its decision record in the same PR (`docs/decisions/README.md`; procedure `.omp/skills/decision-record-lifecycle/SKILL.md`; check `make decisions-verify`). An escaped defect meeting `docs/postmortem/README.md` criteria gets a postmortem whose lessons land as a named test, gate, or rule.
- Any non-obvious lesson costing >30 min becomes a dated entry in `## Important Development Notes`; the third same-class incident becomes a lint rule or hook. Notes cap at 10 and are pruned at milestones.
- Lockfile changes accompany a manifest change; `src/lib/i18n/` is regenerated by `npm run i18n:parse`, never hand-patched; snapshot updates are reviewed hunk-by-hunk.

### Known blind spots (handed to review)

- Coverage gate proves lines ran, not that assertions are meaningful; per-file ratchet on modified upstream files accepts pre-existing violations — "no worse" is not "clean".
- Scoped jscpd compares fork-changed files with each other only; duplication between new code and untouched upstream code is invisible — reviewer greps before accepting a new helper.
- doc-gate checks target and file existence, not that a documented command does what the prose says. CI and the local `make check` overlap but are not identical: only CI runs the runtime layer on a clean Ubuntu runner.
