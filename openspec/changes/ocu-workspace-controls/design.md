# Design

## Context

ChatControls already mounts Files through both responsive panel branches and owns native special-panel exclusion. Chat.svelte owns `initChatHandler`, the authoritative unsaved-chat persistence/adoption path; the server assigns the saved id. Workspace state and ordered preference writes already live in `stores/ocu.ts`. OCU source013e77e2cdf08af30c05694660899fe3f03b8f15 exposes selected runtime modes with dedicated CSP.

## Goals / Non-Goals

Complete issue30 controls and observable policy without reimplementing Files, saving, CDP or ttyd. Issue32 supplies event/poll/history/link producers; this slice supplies and tests the policy those producers consume, not a second polling loop. No Docker, schema/API/dependency changes or native message-renderer edits. Actual sandbox interaction remains issue36.

## Decisions

- Keep a workspace action reachable from ChatControls even when its panel is closed; reuse existing responsive panel/specialPanel/close hooks rather than adding a second sidebar. The action is feature-gated and available to saveable unsaved/saved non-embedded chats. Both temporary-mode store and temporary/local/channel/default id predicates exclude it. No feature-off/temporary request or save attempt is permitted. Do not modify Navbar or Markdown components; place the action within the existing ChatControls ownership boundary and verify narrow/wide layouts for overlap.
- Add `ensureSavedChat: () => Promise<string | null>` from Chat.svelte. It returns a saved id or calls the existing initialization path exactly once for the current unsaved context. Repeated activation shares pending work. The initialization result may adopt chat id/URL/folder state only while the originating chat/history context remains current and temporary mode remains off; failures remain visible and issue no workspace request. Preserve current prompt, history, models, params, attached controls files and folder semantics. If sending a message overlaps workspace persistence, the send path must await that same pending save before deciding whether to create a chat; do not duplicate createNewChat or reserve a client UUID the server ignores. Keep fork coordination outside the upstream spine where practical; any required spine guard/await is hook-sized and covers this transaction only.
- Coordinate both creation orderings. If a normal first Send starts while the id is empty, the workspace action remains visible but disabled with a pending-save explanation until the completion endpoint returns its authoritative `res.chat_id` or fails; the callback also refuses a parallel create while that first-send transaction is pending. If workspace persistence starts first, Send awaits the shared save and uses its returned id. Tests delay each producer independently and prove one chat, current-context adoption and message/workspace binding. Pre-saving an empty chat must preserve the normal first-message title/tag generation settings; track the workspace-precreated first-message case rather than globally enabling background generation for existing chats.
- Workspace open/view state and one-time policy remain chat-keyed. Keep explicit `userClosed`, `autoOpened` and acknowledged revision semantics separate from `dirty`, which listing application clears. First nonempty accepted listing can open once unless userClosed; manual close sets the latch, further accepted revisions mark a change indicator without reopening. Explicit open clears the indicator and may reopen a user-closed panel. A/B switching does not transfer latches or selected views. No localStorage identity or second global panel state authority.
- Policy is applied at existing accepted listing/revision boundaries and consumed reactively by ChatControls. Component/store tests supply accepted changes at that public state boundary and assert actual panel/button behavior. Issue32 later wires external hints/reconciliation/history into this same boundary. Do not claim background first-output discovery or restart restoration before that producer lands.
- WorkspaceArtifact adds view controls. Files remain available when stopped; Browser/Terminal are enabled only when describe advertises them for a running workspace with validated same-origin base_url. Empty outputs do not disable runtime views. Runtime frame URL is exactly the validated base preview path for the current chat with `embed=browser` or `embed=terminal`; fixed sandbox is allow-scripts allow-same-origin allow-forms. No user settings, raw CDP URLs, dynamic sandbox ports or model-supplied URLs are accepted. Switching away destroys the runtime iframe; same-chat streaming and unrelated store updates must preserve the active frame element.
- Selecting a runtime view preserves selected file identity for return to Files. Persist view/open through the shared per-chat preference queue, including explicit close without losing file selection. Retire work on close/chat switch; late save/describe/prefs completions cannot open or populate a different chat. Native Artifacts/Embeds/Call overlays remain mutually exclusive but otherwise unchanged.
- Wrap all workspace user-facing strings through existing i18n context and reuse existing keys where possible. Parent runs the canonical parser for generated locale files; no hand-edited locale translations. DOM tests provide the existing translation dependency rather than adding a production fallback.
- Extend existing stub runtime status/CDP target/held-WebSocket fixtures only enough for actual merged SPA clients to initialize and close. Reuse recording protocol patterns from issue89; these fixtures do not attest sandbox interaction. Actual WebUI tests prove unsaved persistence ordering, temporary exclusion, A/B delayed describe,20open/close cycles with socket counts, frame identity across ordinary updates, stopped explicit Launch, content-preview label and native Artifact/baseline compatibility. Add a credentialed-document positive control to the existing allHeaders cookie oracle while touching that suite.

## Risks / Trade-offs

Persistence adoption races can navigate the wrong chat → guard at the upstream adoption boundary, not only after awaiting the callback. Shared store updates can remount runtime frames → key only binding/chat/view changes and test element identity. Full native Chat tests are expensive → retain focused policy tests plus real route e2e for actual save semantics. Offline stub protocol sockets are transport evidence, not real ttyd/CDP. Updating the OCU pin requires smoke-proxy and existing Office acceptance to stay green.

## Migration Plan

Consume reviewed OCU source013e77e before enabling new runtime tabs. Feature remains off by default; rollback restores prior Files entry without data migration. Keep existing generation and prefs APIs canonical; migrate all local callers if names change. Parent records exact commands, source/fixture revisions, screenshot evidence and three independent review seats before merge.
