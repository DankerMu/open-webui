## Why

#95: the A-T01 native link-popup path intermittently fails in Linux CI. Every recurrence recorded since PR 100 (#95 comments on PR 246, 258, 279 and 284) has the same shape for the modified-click SVG on Linux Chromium 153.0.8010.12: `readyState=complete`, `proof=null|blocked|blocked|blocked`, but `fixtureEvents=[]`; in PR 258, 279 and 284 the sanitized network record also shows a Playwright `page` event about 14 ms after the document's HTTP 200, so Playwright did attach to the failing target. The same source tree passes on rerun and on macOS. The earlier variant (Playwright `page` event never delivered) predates PR 100, which replaced the `waitForEvent('page')` oracle with a CDP target observer; no `waitForEvent('page')` site remains under `e2e/` (only the lifecycle listener `browser.on('page')` in `watchContextLifecycle`, `e2e/ocu-fixtures.ts:261`), so that variant is historical and is bounded, not diagnosed, by this change; the trace below would record it (`page.event`, `frame.navigated`) should it recur. The issue body's line "Direct surfaces: `e2e/ocu-workspace.e2e.ts` and `e2e/ocu-fixtures.ts`; the two `waitForEvent("page")` sites found under `e2e/` are both in A-T01." is stale: the native observer has four call sites in two spec files (below), and `e2e/ocu-controls.e2e.ts:592` is a different A-T01 (the cookie control).

The popup oracle (`e2e/ocu-fixtures.ts`, `observeNativeOcuPopup` `:546-741`, `readPopupDocument` `:465-490`) reads `window.fixtureEvents` from the popup document. That collector is not part of the document: it is installed by the test's context-level `browser.addInitScript` (`e2e/ocu-workspace.e2e.ts:303-309`, `e2e/ocu-resources.e2e.ts:30-38`), which Playwright injects into a natively created target only once it has attached to it and before it resumes the target. The fixture SVG posts its event from an inline script that runs during parsing (`scripts/ocu_stub_nested.py` `diagram.svg`: `window.parent.postMessage({type:'fixture-svg',…},'*')`, where `window.parent === window` in a top-level popup); the HTML fixture posts from a larger document after resources load. The observer attaches to the new target through its own `Target.setAutoAttach` with `waitForDebuggerOnStart: true` and resumes it in a `finally` (`ocu-fixtures.ts:629-635`) as soon as its own `Runtime`/`Log`/`Network` domains are enabled, without installing anything. If Chromium releases a paused target on the first `Runtime.runIfWaitingForDebugger` from any attached client, the observer's resume can precede Playwright's `Page.addScriptToEvaluateOnNewDocument` for the init script; the SVG's inline script then runs before the listener exists and the projection reports `[]`. If Chromium releases only after every waiting client has resumed, the init script is always installed first and the recorded failures need another explanation. `readPopupDocument` evaluates `window.fixtureEvents ?? []`, so an absent collector and an empty one are indistinguishable in every capture so far. The race is a hypothesis that fits the recorded failures, the SVG-only recurrence and the green reruns; it is not yet established, and the experiment below decides it.

Paths are in this repository at `origin/main` `3af0903`.

## What Changes

Test and harness surfaces only; no product, proxy, CSP, sandbox, timeout or dependency change. One CI change (artifact retention), flagged.

- **One collector source.** `e2e/ocu-fixtures.ts` exports `FIXTURE_COLLECTOR_SOURCE`, a self-guarding script (`if (!window.__fixtureCollector) { window.__fixtureCollector = true; window.fixtureEvents = []; window.addEventListener('message', …) }`), and both context `addInitScript` sites use it instead of their inline copies. A second install (Playwright's and the observer's) is a no-op, so no reset and no duplicate listener.
- **Observer-owned install.** In `observeNativeOcuPopup`, for the selected target, the attached session sends `Page.enable` and `Page.addScriptToEvaluateOnNewDocument` with the same source and awaits the acknowledgement before its `Runtime.runIfWaitingForDebugger`. Each client that can release the target (Playwright, the observer) therefore installs the collector before its own resume, so the collector is present whichever client releases first and whichever release semantics Chromium applies. The trace records the install ack before the resume send.
- **Collector state in the projection.** `POPUP_DOCUMENT_EXPRESSION` reports `collector: 'absent' | 'empty' | '<n> events'` and `posted` (the document's own post timestamp); `readPopupDocument` keeps its deadline and poll interval and names both in its timeout message.
- **Timestamped popup trace.** `observeNativeOcuPopup` writes one sanitized JSONL record per observation under `.run/ui-evidence/popup-trace/` (wall-clock ISO timestamps; grants and chat ids redacted through `redactOcu`/`sanitizedLocation`; file named from `test.info().titlePath` and `repeatEachIndex`): click start/end; `Target.targetCreated`/`attachedToTarget` with `waitingForDebugger`; collector install ack; the observer's resume send and ack; `Runtime.executionContextCreated`; `Page.frameNavigated`; the canonical document request, redirect and final response; the context's Playwright `page` event, if any; each poll's `readyState`, `collector` and `posted`. The fixture documents set `window.__fixturePosted = Date.now()` immediately before each `postMessage`. CI retains `.run/ui-evidence/popup-trace/**` in the `workspace-browser-failure` artifact (`.github/workflows/ci.yml`, a CI change).
- **Release-semantics experiment (attribution, not a gate).** A diagnostic-only spec `e2e/ocu-popup-release.e2e.ts` attaches to the new target with `waitForDebuggerOnStart: true`, enables `Runtime`, `Page` and `Network`, and deliberately never resumes from the observer session; it polls the full document projection (granted `path`, `#proof` present, `readyState`) for up to 20 s, records whether the document request was sent and whether Playwright exposed a `page`, then retires through `retireBrowserTargets`. Outcome A (projection completes without the probe's resume): first-resume release, the observer's early resume could precede Playwright's install, the recorded failures are accounted for. Outcome B (document stays paused until cleanup): per-session release, the early resume cannot be the mechanism and the recorded failures remain unattributed by this change. The outcome is recorded verbatim; the oracle change lands in either case because it removes the observer's dependency on Playwright's injection order.
- **Diagnostic repeat entry point.** `scripts/verify-ui-ocu.py` accepts `OCU_UI_SPEC` together with `OCU_UI_REPEAT` and, when both are set and valid, runs only that spec with `--repeat-each <n>` after the same owned stack bring-up; `playwright.ocu.config.ts` derives `testMatch` from `OCU_UI_SPEC` when set (so the diagnostic spec, excluded from the default list, is collected only then) and keeps its explicit list otherwise; the harness's `browser_env` is an allow-list (`verify-ui-ocu.py:494-501`), so the opt-in path adds `OCU_UI_SPEC` to it, for both the `--list` discovery and the run. Both unset → default run; one set, an empty string, an unknown spec or a non-positive/non-integer repeat → `fail` before the stack starts. An optional `OCU_UI_GREP` (Playwright `--grep`, list form) narrows the repeated spec to matching tests; it is valid only with the pair, an empty value fails, and a value that matches no test fails at discovery. Makefile targets `verify-ui-ocu-repeat` (`SPEC=… REPEAT=…`) and `test-verify-ui-ocu-repeat` (the unit test); AGENTS.md rows for both. `make verify-ui-ocu` is unchanged and keeps the all-specs discovery check.
- **Red/green that does not depend on reproduction.** The mutation keeps the sidebar and direct-tab polls alive and starves only the native popups: the context-level `browser.addInitScript(...)` in `ocu-workspace.e2e.ts:303` becomes a page-level `page.addInitScript(FIXTURE_COLLECTOR_SOURCE)`, a `direct.addInitScript(FIXTURE_COLLECTOR_SOURCE)` is added after `browser.newPage()` (`:498`) and before its first `goto`, and the `beforeEach` in `ocu-resources.e2e.ts:30-38` installs on `page` instead of the context. Page-level scripts cover that page and its iframes but Playwright does not hand them to a natively created popup target. Red: under this mutation the pre-change observer reports `collector: absent` for the HTML and SVG popups (the oracle depends on Playwright's context injection). Green: under the same mutation the post-change observer reports `<n> events` on every run and every A-T01 assertion passes; the mutation is then reverted byte-identical and the unmodified spec passes again. The native Linux repetitions are attribution evidence, not the gate.
- **Evidence.** `docs/evidence/issue-95/2026-10-2x-native-linux-popup-trace.md` with the experiment record, the repetition table (20 runs of `ocu-workspace.e2e.ts` before and after the oracle change on native Linux), sanitized trace excerpts, the Chromium/Playwright versions; an #95 comment with the mechanism, what remains unattributed, and the oracle; a decision record (the oracle owns the collector); the archive of this change.
