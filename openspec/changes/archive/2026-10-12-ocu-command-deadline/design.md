# Design

## Context and Existing Mechanism

Command-specific probes confirm `unreachable` before DNS release while `asyncio.run` remains in `Runner.close` awaiting the default executor. Keeping the same command client on an already-running loop removes that wait. The diagnostic uses a shortened test budget; final acceptance uses the unchanged production budget.
The callback path already captures its request loop, offloads blocking ownership with `run_in_threadpool`, and submits downloads with `run_coroutine_threadsafe`. Its single-default-executor-worker regression documents why the blocking owner and DNS worker must not share that executor.
A candidate using the shared AnyIO pool for save passed40 owning tests but failed an induced-callback probe: one available worker slot remained occupied by the save waiter, producing502 at10s before its callback could run. Changing only save dispatch to the prior default-executor domain restored callback200/save202, but that domain cannot satisfy the separate one-worker DNS contract. Save therefore needs an independent blocking-worker owner; this is preservation of callback progress, not a new global-capacity guarantee.

## Governing Invariant

An application command's synchronous wait ends within its existing budget without waiting for resolver shutdown; each caller retains its current lock and state-transition ownership. The running service loop, not a per-command loop or global replacement loop, owns outstanding asynchronous resolution.

## Decisions and Change Surface

Keep async `forcesave` and `lookup_key` as the single command protocol implementations. Existing admitted-cancellation tests consume these APIs; converting them to sync would expand scope.
Add one typed synchronous bridge in `commands.py`: submit a command coroutine to the supplied running loop, wait only for the remaining budget, cancel the submitted future on timeout, and return the caller's corresponding `UNREACHABLE` outcome on timeout/cancellation. Preserve other exception semantics. Unavailable-loop admission must dispose of an unsubmitted coroutine rather than leak it; it reports unreachable. Do not add retries or change DNS resolver policy.
Capture the request loop in async create/save/close handlers before worker dispatch. Pass it explicitly through `_create_session`/`_reopen_session`, `_save_session` and `_close_session`. History restore also calls the shared `_reopen_session`: capture its actual request loop and pass it through `restore_version` → `_restore_version` → `_reopen_session`. No module-global loop, implicit fallback or optional per-call-loop compatibility path.
Use the existing Starlette worker boundary for locked lookup callers, including history restore and the Office session-sweep tick. Save is the exception: dispatch the entire existing synchronous `_save_session` through a private lifespan-owned `ThreadPoolExecutor()` with the runtime's standard defaults, not through either the DNS/default executor or callback AnyIO admission. Copy context per submission and directly await the wrapped executor future, preserving prompt request cancellation, continued work/reconciliation for already-running saves and cancellation of work still queued.
Pass the reaper's running loop explicitly into `sweep_office_sessions` and its lookup visitor. Publication-only sweep and sandbox lifecycle behavior remain unchanged.
Migrate every direct helper/sweep caller, including tests and child-process scripts. Reuse existing TestClient portals or blocking-portal test patterns; retain a real running loop for each synchronous caller.
Implement the isolated lifetime in `office/save_workers.py`, with `save_worker_lifespan(app)` and `run_save_worker(app, callable, *args, **kwargs)`. Publish `app.state.office_save_executor` only after cleanup ownership is ready. Submission reads the active owner and submits without an intervening await; missing/closed ownership fails loudly without pool fallback or a false DocumentServer-unreachable result.
Create the private completion future, stop event, executor and shutdown supervisor before admitting work; start the supervisor before publication. It waits on its event, then calls executor shutdown with waiting enabled and queued work retained, and reports completion/failure through `loop.call_soon_threadsafe`. A genuinely unstarted supervisor has no admitted jobs and can synchronously close the unused executor without a join. If startup raises after acquiring a supervisor, signal and drain/join that acquired owner before propagating the failure. Every later startup/body/teardown exit withdraws admission and signals shutdown.
Drain the private completion future on the live service loop through repeated asyncio cancellation and enclosing AnyIO cancellation scopes; join the started supervisor before releasing lifecycle dependencies, then propagate cancellation. Neither shutdown execution nor its wait may borrow DNS/default or callback worker capacity. A cancelled request future is not evidence that its actual worker finished.
Enter this owner under the established MCP lifespan before starting the reaper or admitting requests; pool cleanup finishes before the enclosing MCP context exits. Keep the reaper's sweep operations and ordering unchanged. Do not add a worker registry, per-request pool, feature flag or shutdown timeout.

## Must Preserve and Sibling Surfaces

Join/reopen lookup stays under the canonical chat lock: unavailable raises the existing HTTP502 path without orphaning or replacement identity. Close lookup remains locked: unavailable retains existing close allocation/HTTP202 semantics rather than inventing a502. Sweep lookup remains locked: unavailable preserves current state. Save sends forcesave after releasing the lock, then retains its existing unreachable reconciliation and save-sequence response.
History restore retains locked reopen admission and existing precedence: an editing session with a known key returns409 `session_open`, an unavailable key lookup returns502 without persisted changes, and an unknown key retains the existing orphan/restore transition. Only loop propagation and worker dispatch change; restore publication/state logic does not.
Keep signing/envelope validation, URL selection, redirect refusal, proxy/cookie policy, response-size bounds, command outcome mapping, existing async command cancellation, workspace bytes, versions, receipts and unrelated session records. Callback/download source and their ownership remain unchanged.
Sibling audit: async command protocols; synchronous bridge; create/join/reopen; close; save/reconciliation; history restore's request/worker/shared-reopen chain; Office poll; direct test/child-process callers; request worker versus DNS executor.

3. Implementer performs the complete loop/worker cutover and caller migration. Parent checks GREEN for both command kinds and join/reopen, close, sweep and save; observes lock competitors while DNS is still held and validates each caller's distinct state/result.

Also require an induced authenticated callback to finish before an accepted forcesave response with one available AnyIO worker. Qualify wrong DNS-worker placement and the shared-callback-worker candidate as rejected controls. 5. Parent runs affected Office/HTTP-origin/lifecycle-lock and new owner suites through canonical discovery, scoped lint, actual HTTP command fault smoke, source identity and secret checks. Targeted owner/cancellation evidence runs on the available production Python3.12 and primary Python3.13 environments. Document after runtime proof; three-seat cross-review and exact-head merge gates.
   Timing starts before command submission or the enclosing operation, never at DNS entry. Final held-DNS cases capture the unchanged10s budget and use the existing150ms scheduling allowance solely as a local regression bound, not an added production timeout or SLA. ## Risks, Non-Goals and Rollback

A resolver thread can outlive a command deadline until the OS resolver returns; this change neither kills threads nor certifies process shutdown time, global executor capacity or deployment latency. No request retry, telemetry, timeout change, lookup relocation, forcesave-under-lock, state-machine redesign or callback/downloader repair.
The loop must remain service-owned and responsive enough to process cancellation; the synchronous wait still has its own budget. Do not claim cancellation prevents every possible already-admitted external side effect.
One atomic source cutover plus central evidence; rollback by reverting the source change. No data migration, feature flag or parallel implementation. Missing caller migrations or a failing preserved-state assertion block delivery rather than permit a shim.

The private executor retains the full synchronous save transaction because splitting prepare/network/reconcile into naked awaits can abandon reconciliation on request cancellation. Shield-and-drain would delay request cancellation and change queued admission; an unowned background task would lose lifetime authority. The chosen cost is one lazy standard-sized pool and one idle shutdown supervisor per app lifespan. Revisit if cancellation semantics or an explicit capacity policy changes, not by silently moving the waiter back into a shared pool.
