# Proposal

## Why

The selected ONLYOFFICE image lets a native presentation module execute before its undeclared base dependency, aborting fresh editor initialization. A real loader-dispatch counterexample and restoration control establish the missing dependency; the owner approved a minimal derived image rather than a verifier workaround.

## What Changes

- Add a hash-bound, reviewed native dependency patch recipe based on the existing immutable ONLYOFFICE 9.4.0 image. Preserve branding, licence notices, server binaries, fonts and native browser policy.
- **BREAKING:** DocumentServer becomes a source-built seventh release role, using the existing offline image inventory/build/import/startup mechanisms. Reject obsolete pulled-role provenance instead of accepting an unpatched image as the repaired artifact.
- Bind local verification to qualified platform-specific built identities and the selected OCU recipe, without a registry push, mutable-tag trust or a second release pipeline.
- Partially supersede B1's unmodified-image premise and the affected pending Office contracts. Preserve historical evidence; qualify the changed native surface and record inherited observations with byte-identity evidence and unchanged limitations.

## Capabilities

### New Capabilities

- `ocu-office-derived-image`: native module ordering, confined derivative provenance, qualified image selection and B1 delta acceptance.

### Modified Capabilities

- `ocu-offline-image-delivery`: synchronize the already implemented seven-role/font-bundle contract and replace only DocumentServer's pulled-image rule with the reviewed source-build rule. Retain all import, startup, source binding and offline guarantees.

The corresponding requirements in the still-open `ocu-office-editing` delta remain aligned; that larger change is not archived or declared accepted here.

## Impact

OCU owns the image recipe, patch inputs, qualification identity declaration, release role and owning deployment tests. WebUI owns the shared contract, decision and evidence. The local verifier's selected-image consumption is migrated in-checkout for qualification, with pre/post source fingerprints; its untracked scripts remain paused #172 deliverables and are not staged in this companion. #172 retains its own delivery, review and acceptance.

Fixture level: **expanded**. Selected risk packs: image/build entrypoint, configuration and identity, file mutation, provenance schema, supply-chain trust, asynchronous module ordering, discovery completeness, compatibility cutover, failure/cleanup, packaging and documentation. No application authorization, broker state machine, font packaging, service topology or project dependency upgrade is selected.

Authorization: [minimal derivative and B1 update](https://github.com/DankerMu/open-webui/issues/433#issuecomment-6211006595). [Confirmed failure and restoration](https://github.com/DankerMu/open-webui/issues/433#issuecomment-6210769448). No LAN deployment, acceptance-machine access or expansion of #197's other image work.
