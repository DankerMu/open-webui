# Design

## Context

Source authority: issue15 task9.1/9.3; parent D8/D11 and outputs-reconciliation. User decision5790293452 permits initial/detected-change hashing and bounds path-reuse guarantees to observed deletion. Existing app.list_outputs scans BASE_DATA_DIR/chat/outputs; issue13 supplies the shared RLock+flock transaction. No broker exists.

## Governing invariant

One committed index is the per-chat identity/revision authority: reconciliation either atomically publishes a complete valid successor or preserves the previous index. Live sandbox writers do not acquire this lock; it serializes broker/lifecycle workers, not file contents.

## Decisions

- OutputsBroker uses configured BASE_DATA_DIR and the same canonical chat and combined lifecycle lock as docker_manager. Hold it across index read, scan, delta computation and atomic replacement. No Docker calls. Test roots use isolated configured BASE_DATA_DIR, not a second lock registry.
- API: `reconcile(chat_id, *, cursor=None, limit=100)` returns a listing with revision, entries, total, next cursor and unchanged indicator. Entries carry UUID file_id, relative POSIX path, basename, size, mtime_ns, revision and cached SHA-256. HTTP metadata/type/mime/url and If-None-Match wiring remain #16. A read-only current-revision accessor reads/validates the same index under the lock for #16 describe; it must not instantiate or resume a sandbox.
- Index stores a schema version, global counter, active entries keyed by path, fingerprint→one-or-more active ids and tombstones keyed by deleted id. Fingerprints are not unique: equal-content files have separate UUIDs. Persist enough state to retain stamps across process restarts; malformed schema/JSON fails closed, never resets the counter.
- Match existing active paths first. Same-size entries retain id/revision/hash regardless of mtime; mtime is display only. Size changes retain id, stream a fresh hash and increment the counter. New paths are hashed once. Pair missing active entries with new paths of equal size/hash in deterministic old-path/new-path order, one-to-one; a rename retains id and increments once without tombstoning that still-live id. Only removals in the current reconcile are rename candidates, never historical tombstones.
- Unmatched removals become tombstones and increment the counter; unmatched additions receive new UUIDs and increment it. Each changed entry/tombstone gets its event's counter; unchanged entries retain theirs. A path recreated after an observed deletion never inherits its old id. Delete/recreate entirely between observations and same-size in-place writes remain explicit blind spots.
- Scan regular non-hidden files beneath outputs without following symlinks, including symlink directories. A symlinked outputs root fails explicitly. Anchor traversal/opening to directory descriptors and use no-follow file opens so path races cannot read outside outputs. A disappearing/changing file during scan/hash yields a retryable reconciliation error without committing a partial index; no automatic unbounded retry. Compare file observations for read stability, never as durable identity.
- A missing outputs root is empty only on first use or when the index has no active entries. With active entries, report a retryable error and preserve the index; restoring the root must retain those identities.
- Defaults: page100, maximum page1000, maximum active files10000, maximum file size100MiB, maximum index size64MiB. Constructor limits may be lowered for tests or explicitly configured by the later endpoint owner; invalid limits fail immediately. Oversized inputs/index fail explicitly with old index preserved, not truncated listings or false tombstones. Hash in bounded chunks, not whole-file reads.
- Pagination sorts relative paths and uses a cursor carrying listing revision and offset. Validate cursor shape/range; reject a cursor from an older revision rather than mix pages. Limits count before paging; return total and next cursor. Always scan metadata before deciding unchanged because sandbox writes are external; do not use a client revision to skip discovery. Unchanged scans hash zero files and do not rewrite the index; current mtime values may still be returned for display.
- Write a same-directory temporary index under the lock, flush/fsync and atomically replace; sync the containing directory for successful durability. Clean temporary files on precommit error and preserve the previous index. Atomic replacement is the commit point: a later durability error is reported explicitly but may leave the complete new index visible, never a partial index or silent counter reset. Reject symlinked control/index paths rather than follow them. Missing index is first use; losing the index externally is not a supported reset/restore path.

## Boundaries and evidence

The pure module is intentionally not endpoint-wired in issue15 (explicit issue exception); add Dockerfile COPY so issue16 can import it in the image. Existing lifecycle helpers remain the single lock authority. Public broker methods get real-filesystem tests, not JSON mocks: rename, duplicate-content one-to-one identity, observed reuse, forged-mtime size change, unchanged5000 no hashes/no rewrite, pagination/stale cursor, process restart/contention, corruption/failed replacement, symlinks and configured bounds. Strictly no Docker daemon.

Full write detection, event watching, same-size edits, immutable content snapshots, HTTP routes/URLs and UI behavior are non-goals. Index/tombstone storage is bounded; reaching the configured index limit requires operator handling rather than silent history loss. Review focus: prior-hash authority, tombstone non-resurrection, shared-lock atomicity, path safety and truthful unchanged evidence.
