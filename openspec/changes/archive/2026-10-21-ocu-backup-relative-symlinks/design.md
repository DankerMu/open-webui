## Design

Change surface: `deploy/recovery_fs.py` (`inspect_archive` symlink predicate, `_python_capture` symlink predicate, one new private helper), `deploy/recovery_resources.py` (`capture_volume`, `restore_volume` error text), `deploy/BACKUP-RESTORE.md`, `tests/deploy/test_recovery_fs.py`, `tests/deploy/test_recovery.py` (or a resources test module if one exists).

Must preserve: absolute symlinks refused; any link that resolves outside the archive root refused; hardlink rules (`:357-359`, `:400-406`) unchanged; members under a symlink or hardlink ancestor refused (`_reject_link_escapes`); every symlink accepted at 34dc83c except the empty target stays accepted (all non-empty targets without `..`, including `alias -> notes.txt`, `./y`, `a//b`, `a/`, `.`, `./`); capture and restore validate with the same predicate, so anything capture publishes restores and nothing restore accepts was refused at capture; GNU tar and Python paths behave the same; `_volume_has_marker` keeps treating a non-zero probe as "marker absent".

Must add/change: `_symlink_target_confined(member_name, target) -> bool`. Refuse when the target is empty, starts with `/` or contains `\x00`. Split on `/` and drop `.` and empty components (the normalisation `Path(target).parts` applies today, which does not change where the link resolves). Refuse when a `..` component follows a normal component. Let k be the number of leading `..` components and d the number of components in the canonical member name minus one (the parent directory depth; a root-level member has d = 0). Accept only when k <= d. No normal component is required: `.` or `./` (k = 0) points at the link's own directory and a run of `..` with k <= d points at an ancestor inside the root, both accepted today or inside the root by the invariant. The empty target stays refused (it cannot be created on Linux and is not a valid link). Both `inspect_archive` and `_python_capture` call it; `_python_capture` computes the member name from `relative`.

On-disk parent check (fix pass 1, PR #161 round 1): `_reject_link_escapes` compares member names as strings, but on a case- or normalisation-insensitive filesystem (APFS/HFS+, casefold ext4) two different names can address one directory entry. With `d/L -> ..` accepted, `d/l/M -> ../..` (name depth 2) is created through `d/l` = `d/L` at the root and climbs two levels above it, and `d/l/m/evil` is then written outside the destination by `_python_extract` (reproduced on APFS; refused at 34dc83c because every `..` link was refused). `_python_extract` therefore refuses, before creating any member or applying its metadata, a member whose parent chain below `dest` contains a symbolic link or a non-directory on disk (lstat of each existing ancestor; ancestors it creates are real directories), with `{archive}: unsafe parent {name}`, and refuses a member whose own path already exists on disk (unless both are directories) with `{archive}: existing target {name}`, so a reversed member order (`d/l/m/evil` before `d/L -> ..`) fails as a `RecoveryError` instead of a raw `FileExistsError`. This restores the invariant's premise independent of filesystem name rules. The GNU tar path keeps GNU tar's own handling (it defers `..` symlinks as placeholder files until the end, so a later member cannot be created through one); the post-extraction `validate_archive`/walk is unchanged.

Governing invariant: following any accepted symlink from its real parent directory, by real path resolution, never leaves the archive root. Reason: the parent chain is all real directories (`_reject_link_escapes` by name; on disk by the extraction parent check below), so the leading `..` run climbs exactly k real levels and stays at or below the root; the remaining components contain no `..`, so descending through them, including through other accepted links, stays inside the root by induction.

Archive root decision: the predicate confines links to the archive root, not to narrower trust boundaries inside it. The chat-data archive root is the whole chat directory, so a link `chatA/outputs/y -> ../../chatB/x` (created through a sandbox's `/mnt/user-data/files` bind, `recovery_resources.py:349`) is now captured and restored where it failed the backup before. Accepted, because restore recreates exactly the source state inside the owned destination, host readers never follow workspace links (`computer-use-server/uploads.py:381` skips them; `outputs_broker.py` does not follow symlinks (`follow_symlinks=False` at `:545`, `:618`; `O_NOFOLLOW` required at `:120`), ; the restore-time `_broker_listing` index read (`_index_snapshot`) can follow a link, but a root-level `chatA -> chatB` link without `..` already gave the same redirection at 34dc83c, so no new capability), and inside a sandbox the link points outside its mount and resolves to nothing. A test pins that such a link round-trips unchanged.

Compatibility direction: sets captured with this rule can hold `..` links that recovery tooling at 34dc83c or older refuses; verify and restore must use tooling with this change. Documented in BACKUP-RESTORE.md; no reader for old tooling is added.

Sibling surfaces: producers: GNU tar capture (`capture_tree` `:285-299`) and Python capture (`_python_capture`), both followed by `validate_archive`; validators: `inspect_archive`, `_reject_link_escapes`, `_reject_destination_conflicts`; consumers: `extract_tree` (GNU tar `EXTRACT_FLAGS` and `_python_extract`, which `os.symlink`s the stored target verbatim), `recovery_resources.capture_volume`/`restore_volume` (WebUI data and workspace volumes, through the helper image), chat/skills tree archives through `capture_tree`; failure paths: helper non-zero exit in `capture_volume`, `restore_volume`, `_broker_listing` (already detailed), `_volume_has_marker` (intentionally silent).

Seams under test: `capture_tree`/`validate_archive`/`extract_tree` on real temporary trees and hand-built tar archives; `capture_volume`/`restore_volume` with `run_volume_helper` replaced by a fake returning a failing `CompletedProcess`.

Required evidence:

- Tree `models--x/blobs/abc` (file) and `models--x/snapshots/r1/model.safetensors -> ../../blobs/abc` plus `models--x/snapshots/r1/1_Pooling/config.json -> ../../../blobs/def`: `capture_tree` succeeds; `extract_tree` into an empty directory recreates both links with the same targets, and reading through them returns the blob bytes. Red on `34dc83c` (`unsafe symlink`), on both the GNU tar path and the Python fallback.
- Hand-built archives each refused by `validate_archive`/`extract_tree` with `unsafe symlink` and nothing created in the destination: root-level `x -> ../y`; `a/x -> ../../y`; `a/b/x -> a/../../../y` and `a/x -> b/../y` (later `..`); `a/x -> /etc/passwd`; `a/b/x -> ../../..` (k = 3 > d = 2); `a/x -> ""`.
- Still accepted (compatibility): `a/x -> ./y`, `a/x -> b//y`, `a/x -> .` and `a/x -> ./` round-trip with targets unchanged; `a/x -> ..` (k = 1 = d) is accepted; a cross-directory link inside the root (`chatA/outputs/y -> ../../chatB/x`) round-trips unchanged.
- Path coverage: the GNU tar tests assert `_gnu_tar()` is true and skip with the reason `GNU tar unavailable (bsdtar on macOS)` otherwise; `build.yml:254` would run them on ubuntu, but that workflow is `disabled_manually` on DankerMu/open-computer-use, so the GNU evidence is a CI-shaped Linux container run (`python:3.13`, non-root, GNU tar, `pip install -r computer-use-server/requirements.txt pytest pytest-asyncio PyYAML`, `python -m unittest discover -s tests/deploy -v`) on head and on 34dc83c, with the log attached to the PR. The Python fallback tests force `_gnu_tar` false and run everywhere.
- `capture_tree` of a real tree containing `a/x -> ../../outside` fails `unsafe symlink` (Python fallback: the capture-time message).
- `capture_volume` with a fake helper result (returncode 1, stderr `RecoveryError: /output/x.tar.gz: unsafe symlink a/b`) raises a `RecoveryError` whose message contains both the volume name and `unsafe symlink a/b`; stderr longer than 2000 characters is cut to its last 2000; empty stderr falls back to stdout; `restore_volume` likewise.
- The case-alias archive (`.`, `d`, `d/L -> ..`, `d/l/M -> ../..`, `d/l/m/evil`) extracted with the Python fallback into `<tmp>/x/y/dest` on a case-insensitive filesystem fails `unsafe parent` and leaves nothing outside `dest` (skipped with a reason when the temporary filesystem is case-sensitive). Red on head `7c425fe` (the file appears at `<tmp>/x/evil`). Filesystem-independent: `_python_extract` of an archive whose member's parent is a pre-existing on-disk symlink inside `dest` is refused before writing through it.
- Existing `tests/deploy`: the failure set on head is no larger than on 34dc83c in the same container (all failures environment-only), and no new test fails.

Non-goals: absolute links in workspace volumes (for example a venv's `bin/python -> /usr/local/bin/python3`) still fail the backup; tracked as #596. Excluding the embedding cache from capture (owner decision; not needed once links are accepted); cross-daemon restore evidence (#173 B-T14 still untested); hardlink policy.

Review focus: the predicate against the invariant, including root-level links and links whose target walks through another accepted link; capture/restore symmetry on both tar paths; that no consumer follows a link before validation; error text bounded and free of secrets (helper output only contains paths and messages).
