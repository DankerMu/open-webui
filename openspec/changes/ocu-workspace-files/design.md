# Design

## Context

Canonical workspace-sidebar requirements remain the epic target. This slice owns Files and a minimal real saved-chat entry, not issue30's unsaved-chat persistence/auto-open/Browser/Terminal or issue32's history/socket/link interception. The API now throws WorkspaceRequestError; the OCU Office iframe exposes the merged ocu-preview-spa parent protocol.

## Decisions

- WorkspaceArtifact takes chatId. Keep state in existing stores/ocu.ts, not artifactContents; use generations on mount/reconcile and invalidate on unmount/chat change. No separate workspace identity or global iframe state. A saved-chat-only Files entry in ChatControls opens the new special panel and closes it using existing panel lifecycle; native Artifacts remains unaffected.
- Expose ENABLE_OCU_WORKSPACE as an authenticated config feature with a hook-sized main.py change using the existing router flag authority. Read it through a typed narrow OCU helper accepting the config object; do not widen upstream stores/index.ts or invent a second env flag. Missing/false means no entry, no mount, no requests. Temporary/local/channel/default/empty chat IDs are refused.
- Describe supplies status/capabilities/base_url; proxied outputs supplies files/revision/next_cursor. Use base_url from describe, validate same-origin path, and never navigate a model-supplied URL. Extend existing API client for proxied listing with cookies and no internal token. File links must match the current chat's canonical broker path before preview/download.
- Render unavailable/loading/ready/empty/error/stopped/disconnected distinctly. Launch exists only when capability permits; Retry/Reconnect repeat describe/listing, not implicit launch. Stopped files remain browsable. Request failures never become empty lists. Keep loaded data with an explicit failure notice when refresh fails.
- Pagination keeps coherent revisions; a stale cursor restarts at most once, incomplete chains never clear selection. More appends the next authorized page. Selected file_id survives rename and refresh by identity; absence requires complete enumeration before clearing selection and PUT prefs selected_file_id:null. Preserve known view/open prefs when replacing prefs; no restart-history restore claim in this slice.
- Generated HTML/SVG/XML uses a direct cookie-path src iframe with exactly allow-scripts allow-forms, never srcdoc, injectCsp or user sandbox settings. Office docx/xlsx/pptx uses `/preview/{chat_id}?embed=files` under describe base_url with exactly allow-scripts allow-same-origin allow-forms. Parent validates exact frame source/origin/schema/chat/file/generation, waits for ready, then sends monotonically increasing requests. New selection/revision invalidates stale results. Error/unsupported states retain the parent download link; iframe downloads are not required. Other types get honest supported direct preview or a named download-only state, not fake corruption.
- Office handshake has a10-second deadline and each selected-file terminal outcome a30-second deadline after dispatch. Timeout retires that frame/selection generation, shows a named error with parent download and explicit Retry; late ready/success cannot dismiss it. Retry creates a fresh frame handshake/generation. Selection change, close and unmount cancel both timers.
- A-T01 covers sidebar iframe, a real rendered message file link opened in a new tab, and direct new-tab navigation, including scripted SVG. It does not implement issue32's future click-to-sidebar interception. Assert opaque security behavior via blocked storage/parent access and message event.origin null, not obsolete document.origin or URL-derived location.origin alone. Inline JS/CSS/data URI works; relative stylesheet401 is the explicit D19 limitation, not an application console-error exemption.
- Browser harness reuses existing proxy materialization/lifecycle helpers and stub, with proxy upstream pointing to the actual Vite SPA. Add deterministic per-chat fixtures keyed by real owner chats; no production fixture-control route. Serve real merged OCU Office assets for at least one valid/corrupt integration, not an echo iframe. Update the existing OCU pin to reviewed2da9b60a3f62d6716821d631c72b1e3af3851870 only because this consumer needs that interface, then rerun proxy smoke. CI checks out that pin. Disable HMR for the dedicated harness rather than suppressing console errors.
- The verify-ui workspace harness owns an isolated backend/Vite/stub/proxy process set on fresh loopback ports; it never reuses or stops the default dev-bg servers already running in local/CI. Reuse shared startup environment/asset staging and owned-process helpers rather than duplicate a second policy. Its backend uses the registered stub URL/token from process start, Vite targets that backend with HMR disabled, and Playwright does not auto-start/reuse the default server for this run. Data stays in `.run/data` under unique fixture identities; tracked frontend assets are staged using the existing harness rule. Before browser assertions, require an actual owner-chat describe fixture and a served real Office asset from the reviewed Git pin. Default dev-bg with a dummy OCU URL may coexist but cannot satisfy readiness. Teardown kills only owned process groups and removes owned fixture state; CI exposes OCU_CHECKOUT to verify-ui, and local missing checkout/commit fails explicitly.
- User-approved jsdom26.1.0 enables real Svelte component lifecycle tests under Vitest; maintain per-file80% gate, no Svelte exemption. Playwright remains the actual iframe/security oracle. Existing make verify-ui must execute A-T01/A-T10 in its supported harness, with isolated owned process lifecycle and cleanup, not silently skip for absent OCU checkout.

## Risks / Trade-offs

Pref read-back is not exposed by describe; cross-restart restore remains issue32. Listing completion can be expensive; bound fetch work and report incomplete/error rather than tombstoning unseen files. The fixed trusted iframe cannot download directly; parent controls downloads. Office assets and proxy config must come from the same reviewed Git pin, without copying ignored deployment files or secrets.

## Migration Plan

Feature remains off by default. Deploy the OCU interface before enabling the Files UI. Rolling back the UI leaves server/OCU contracts intact. No database migration or real-engine operations; issue36 owns deployed acceptance.
