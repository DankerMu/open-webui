## Decisions

- Relative ES module imports. Dynamic local scripts, PDF worker and local viewer addresses derive from import.meta.url. BrowserViewer already demonstrates this base pattern. No root-absolute /static/ literals in authored static JS, including stale example comments; do not rewrite vendored bundles.
- One shared import-safe request module used by preview and browser viewer. Derive public prefix from its own static module URL, not guessed deployment addresses. ocuFetch(url, init) merges Headers and sets X-Requested-With: ocu-workspace, preserving body/method/other headers. Explicit server-URL provenance in a wrapper-only init flag (removed before native fetch) keeps apiUrl/filesBase-derived URLs/entry.url/describeUrl verbatim. Default client root paths receive prefix exactly once with path-segment boundary matching, not naive startsWith. Relative and scheme-absolute URLs are unchanged. Never exempt guessed /api/v1 namespaces instead of marking emitted describeUrl.
- Terminal WS uses the same client path resolver then ws/wss for page protocol. BrowserViewer existing module-derived WS base remains valid. Browser handshakes/assets/media tags cannot attach fetch headers; every application-owned scripted HTTP request uses wrapper, while native browser resource loads retain existing cookie/proxy auth. PDF library-owned document fetch passes the same request header through its supported httpHeaders option. No token is placed in browser config/JS.
- Move the120s inline shell heartbeat into the wrapper-managed SPA effect; remove old inline timer, keep cadence and clean up on unmount. This follows issue17's explicit heartbeat amendment. Header-free original test literals are not a contract to preserve.
- Issue17's inline-heartbeat ownership amendment permits moving emission into the SPA; it supersedes the parent requirement's literal HTML-shell emission point, not its prefix/header guarantee. Update that parent wording when this fixture lands.
- ActiveCliBadge reads exactly emitted describeUrl and data.cli_badge, never runtime-cli. Failure hides badge without a retry loop or guessed API fallback. Both __stopped__/__meta_exists__ buttons POST the existing restart-container launch alias, then start ttyd only on success; no new route and no implicit launch during polling.
- Keep broker path ordering. Revision rather than mtime is the sole render key: path+entry revision, with stable object identity on unchanged keys to retain scroll/view state. Preserve selected file_id across rename; changed path/revision reloads it. Removal clears or selects an existing file, never leaves deleted content selected. Existing unrelated-file auto-selection policy must not steal focus from an explicitly selected changed Office file.
- First page100 with visible more control when next_cursor exists. More loads an additional page; retain that loaded-page depth on subsequent polls so selected later-page files stay observable. Reconcile a full requested page chain into a candidate, commit atomically only when every page shares listing revision. Midchain409 discards candidate and retries from page1 once; other/repeated errors keep prior list and visible error indicator. Latest request generation alone commits; stale responses cannot regress listing revision/selection. No unbounded page loop; stop at requested depth/end, reject repeated cursors. Poll cadence remains3s foreground/15s hidden and resume triggers reconcile. Do not skip discovery on persisted revision; no new ETag cache protocol required.
- Add literal visible 内容预览 label with explanation pagination/layout may differ from Office for DOCX/XLSX/PPTX; localize supporting text using existing locale table. In each XLSX sheet, formula with no cached value is visibly uncomputed; cached0/false values remain legitimate. Do not evaluate formulas. Keep sheet navigation and PPTX per-slide rendering/download fallback.

## Evidence and boundaries

Use existing pytest+Node VM for actual wrapper/module and state transitions; no source-string-only behavior tests. Add deterministic formula fixtures to exercise real SheetJS parsing where practical, not only a mocked renderer. Runtime screenshots use real OCU app/outputs broker/file serving and actual vendored Office renderers; ephemeral host reverse proxy strips /ocu and injects test token server-side, with dependency responses only for unavailable describe/browser/terminal lifecycle. No Docker calls. Do not expose internal token to browser via extraHTTPHeaders as production proof. Host harness can be throwaway under /tmp; no deployment overlay edits.

Host server uses the same pinned Python3.12 uv environment as the orchestrator tests, with requirements.txt and invalid DOCKER_HOST/DOCKER_SOCKET; services run under the parent harness lifecycle. The ephemeral proxy rejects a header-less heartbeat and accepts the wrapped request, proving the request-policy seam without claiming the later production proxy's acceptance.

Generate real OOXML fixtures without committed binary blobs; use existing installed tools or stdlib ZIP/XML. DOCX Chinese/title/table, XLSX multiple sheets/cached formula and uncached formula, PPTX multiple slides and differing deck dimensions with chart/image as the parent acceptance requests. Capture initial and size-changing update screenshots for each, assert new visible content and no new console errors, record renderer compatibility limitations honestly. Same-size edit detection stays broker non-goal; formal Docker A-T01–A-T15 remains#36. Network evidence proves no runtime-cli calls, no doubleprefix/rootstatic requests, exact describe URL and heartbeat header. In-process/HTTP mocks cannot substitute for rendered screenshots.

## Risks / Trade-offs

Async render completion can overwrite a newer selected revision: isolate render generation or staging container and discard obsolete completion, with delayed-response proof. Stable entry reference must not suppress a true revision update. Metadata pagination is a bounded UI window, not silent truncation. The proxy harness is test topology, not production proxy acceptance. Keep HTML sandbox flags and generated-content isolation unchanged.

Output fetches use cache:no-store through the wrapper so a changed revision cannot reuse browser-cached Office bytes. Preserve server-emitted URLs verbatim rather than appending guessed cache-busting query strings. Native media and third-party renderer caching retain existing behavior unless the changed acceptance path requires its supported cache control.
