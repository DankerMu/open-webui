# 工作区上传 Skills

管理员可以把 ZIP 格式的 skill 上传到 WebUI，skill 里可以带脚本，在被授权用户的工作区沙箱中执行。上传的 skill 默认对所有用户开放，管理员可以收窄范围；每个用户可以关掉自己不需要的 skill，也可以在输入框里用 `/` 点名使用某个 skill。

本功能跟随工作区开关 `ENABLE_OCU_WORKSPACE`：关闭时，管理员标签、个人设置标签和 `/` 分组都不显示。OCU 内置的 skill 不受本功能管理：它们不出现在下文任何列表里，不能被禁用，也不能被同名上传顶替。

## 上传 skill

入口：「设置」→「管理员」→「工具」分组 →「工作区 Skills」，只对管理员显示。在「上传」区域的「上传 skill ZIP」一行点击「上传」，选择 ZIP 文件。上传成功后，skill 出现在下方「技能」列表中，显示名字和描述。失败时，服务端给出的英文原因以红字显示在上传行下方。

ZIP 的结构：

- 根目录有 `SKILL.md`，开头是两行 `---` 包住的 YAML frontmatter，其中：
  - `name`：小写字母或数字开头，只含小写字母、数字和 `-`，最长 64 个字符。它就是 skill 的名字，也是沙箱里的目录名 `/mnt/skills/user/{name}`。
  - `description`：非空字符串。
- 所有文件可以包在同一个顶层目录里（例如 `invoice-builder/SKILL.md`），上传时会去掉这层目录，效果与文件直接放在根目录相同。
- `SKILL.md` 须为 UTF-8 编码；开头的 BOM 和 Windows 换行都可以接受。

### 同名再次上传

上传一个 `name` 已存在的 ZIP，会直接原地替换该 skill 的内容和描述，**不会弹出确认**。原有的授权范围和每个用户的开关状态保持不变。替换何时到达沙箱，见[生效时机](#生效时机)。

### 上传被拒绝的原因

ZIP 超过 50 MB 时返回 413。其他所有拒绝都返回 400。被拒绝的上传不写入任何内容，已有的 skill、授权和开关状态都不变。

| 原因                                                                                | 红字提示中的关键词                                                       |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 文件不是可读取的 ZIP，或某个条目校验和不符、声明大小与实际数据不一致                | `not a readable ZIP archive`                                             |
| 条目路径含反斜杠、是绝对路径（含 `C:` 这类盘符）或含 `..`                           | `backslash`、`absolute path`、`'..' component`                           |
| 去掉顶层目录后，路径含空段或 `.` 段；或某个文件的路径落在另一个文件下面             | `non-canonical entry path`、`lies under file entry`                      |
| 条目是符号链接，或既不是普通文件也不是目录                                          | `symlink entry`、`is not a regular file or directory`                    |
| 条目加密                                                                            | `encrypted entry`                                                        |
| 条目的压缩方式不是 stored 或 deflate                                                | `uses compression method`                                                |
| 条目超过 2000 个                                                                    | `entry limit`                                                            |
| 各条目声明的解压后大小合计超过 200 MB                                               | `declared uncompressed size exceeds 200 MB`                              |
| 去掉顶层目录后，根目录没有 `SKILL.md`                                               | `no root SKILL.md`                                                       |
| `SKILL.md` 超过 1 MB，或不是 UTF-8                                                  | `SKILL.md exceeds 1 MB`、`SKILL.md is not UTF-8`                         |
| `SKILL.md` 没有 `---` 包住的 frontmatter，或 frontmatter 不是 YAML 键值对、嵌套过深 | `no frontmatter`、`is not YAML`、`is not a mapping`、`nested too deeply` |
| `name` 缺失或不符合上面的规则                                                       | `frontmatter name must be`                                               |
| `description` 缺失或为空                                                            | `frontmatter description must be a non-empty string`                     |
| `name` 与 OCU 内置 skill 重名（例如 `docx`、`xlsx`、`pptx`、`pdf`、`remotion`）     | `is a reserved built-in skill`                                           |

两个管理员同时首次上传同一个新名字时，后完成的一方会收到 409（`already exists`），重新上传即为替换。

## 收窄可见范围

首次上传的 skill 对所有用户开放。要只给部分用户或分组使用，在「技能」列表中点击该 skill 的「访问」，打开「访问控制」对话框：

- 可见范围默认是「公共」（对所有用户开放）。改为「私有」后，只有「访问列表」里的用户和分组可以使用。
- 点击「添加访问」选择用户或分组，权限固定为「只读」。点击条目右侧的 × 移除。
- 每次修改立即保存，没有单独的保存按钮；保存失败会弹出提示，并重新载入列表。
- 建议先添加用户或分组，再切换为「私有」，避免中间出现没人能用的状态。
- 「私有」且访问列表为空时，普通用户都不能使用这个 skill。

管理员不受授权范围限制：在默认开启的 `BYPASS_ADMIN_ACCESS_CONTROL` 下，所有管理员都能看到并使用每一个上传的 skill。验证收窄效果时，请用普通用户账号检查。

点击「删除」并在「删除 skill」对话框中确认后，skill 连同其授权和所有用户的开关状态被一起删除，无法撤销；取消则不做任何改动。

## 个人开关

入口：「设置」→「个人」→「工作区 Skills」。这里列出你有权使用的上传 skill，每个一个开关；没有可用 skill 时显示「暂无可用的工作区 Skills。」。

- 关闭开关只影响你自己：该 skill 不再出现在你的 `/` 菜单里，你之后新建的沙箱也不再挂载它。其他用户不受影响。
- 开关状态保存在服务端，刷新页面或换浏览器登录后保持不变。
- 管理员替换同名 skill 不会重置你的开关。

## 在输入框里用 `/` 点名使用

在聊天输入框输入 `/`，菜单中的「工作区 Skills」分组列出你已开启的上传 skill；继续输入可以按名字筛选。

- 只列出上传的 skill。OCU 内置 skill 从不出现在这里，模型会根据任务自行决定是否使用它们。
- 你关闭的 skill、无权使用的 skill 不会出现。没有可列出的条目时，不显示这个分组。
- 分组是否显示与当前聊天有没有沙箱、所选模型的配置无关，只要工作区功能开启即可。

选中一项后，输入框里出现该 skill 的名字。发送后，你的消息里只显示这个名字，模型会额外收到一句提示：先阅读该 skill 的 `SKILL.md` 再动手。在不经过 OCU 的模型上，消息里同样只留下名字，但不会附带这句提示。

## 生效时机

上传、授权和开关的改动在**下一个新建的沙箱**生效，撤销也不会立即作用于已有沙箱；替换 ZIP 例外。

| 操作                 | 模型看到的可用 skill 列表                | 沙箱里的文件                                                                    |
| -------------------- | ---------------------------------------- | ------------------------------------------------------------------------------- |
| 上传、授权、开启     | 新对话约 120 秒内；已有对话最长约 420 秒 | 下一个新建的沙箱才挂载                                                          |
| 撤销授权、关闭、删除 | 同上                                     | 已有沙箱里的文件仍然可读，直到沙箱重建                                          |
| 替换 ZIP             | 同上                                     | 正在运行、已挂载该 skill 的沙箱会在约 60–420 秒内看到新内容；新建的沙箱读取缓存 |

管理员标签顶部固定显示两条对应提示：「撤销访问权限或删除 skill 后，运行中的沙箱要在重建后才会生效。」和「替换 ZIP 后，已挂载该 skill 的运行中沙箱会在几分钟内（约 60–420 秒）获得新内容；新建的沙箱读取缓存。」

上传的脚本会在每个被授权用户的沙箱里执行，系统不审查脚本内容。上传前请确认来源可信。

## 撤销与回滚

**撤销某个 skill**：在 WebUI 里删除它，并且此时 OCU 必须能访问 WebUI。只在 OCU 上取消 `MCP_TOKENS_URL` **不会**让 OCU 退回只用内置 skill：OCU 会继续使用磁盘上缓存的用户 skill 列表和已解压的旧目录。OCU 访问不到 WebUI 期间同样沿用缓存，撤销要等下一次成功访问后才生效。

**回滚整个功能**，按顺序执行：

1. 趁 OCU 仍能访问 WebUI，在 WebUI 里删除所有上传的 skill。
2. 在 OCU 上取消 `MCP_TOKENS_URL` 和 `MCP_TOKENS_API_KEY`。
3. 清空 OCU 的 `SKILLS_CACHE_DIR`，包括其中的 `_user_configs/`。
4. 回滚 WebUI。数据库迁移的降级会删除上传 skill 的两张表和它们的授权记录。

## 部署配置

WebUI 不新增环境变量，上传的 skill 保存在 WebUI 数据库中，随数据库备份。OCU 的 `computer-use-server` 服务需要两项配置：

- `MCP_TOKENS_URL`：指向 WebUI 私网地址下的 `/api/v1/ocu/skills`。
- `MCP_TOKENS_API_KEY`：与 `OCU_INTERNAL_TOKEN` 取自同一来源，不写入仓库文件、命令行或日志。WebUI 的 `OCU_INTERNAL_TOKEN` 为空时，拒绝 OCU 的所有 skill 请求。

部署顺序为先 WebUI、后 OCU。OCU 先启动时取不到 WebUI 的 skill 列表，只使用内置 skill，与未部署本功能时一致。部署记录中有一行显示 skill registry 是否已配置（yes 或 no），不显示密钥。
