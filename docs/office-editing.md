# 在工作区编辑 Office 文件

在聊天的工作区文件列表中选择 DOCX、XLSX 或 PPTX，点击「编辑」（Edit）进入编辑器。编辑入口由管理员开启。本文用界面上的英文名称标识尚未翻译的按钮，并附中文解释。

## 保存到工作区

**主动保存请使用 WebUI 状态栏的「保存」（Save），不要把编辑器内部的 Ctrl+S 当作保存到工作区。**

- 修改后，状态栏显示 **Unsaved**（未保存）。点击状态栏「保存」，等待 **Saving**（保存中）结束并显示「已保存」（Saved），再让 Agent 读取文件。
- 编辑器自己的保存命令（Ctrl+S）只把输入送到编辑服务，不写回工作区文件，也不使状态栏变成「已保存」。这些内容要到下一次状态栏保存，或正常离开编辑器并成功完成保存后，才进入工作区文件。
- 切换聊天、关闭侧栏或点击 **Close editor**（关闭编辑器）会尝试保存。请检查离开后的结果提示；失败、冲突或未确认都不等于保存成功。
- 刷新页面或关闭浏览器标签页时，如果浏览器提示存在未保存内容，建议取消离开，先用状态栏保存并确认结果。不要依赖直接关闭页面来完成保存。

## 自动保存与重启后的恢复

编辑期间，有尚未保存的输入时，系统每 5 分钟保存一份可恢复版本，**不会因此更新工作区文件**。编辑服务崩溃或重启时，最近一次自动保存之后的输入可能丢失，最多涉及 5 分钟的输入；重要修改应主动保存。

重新打开文件时，如果有尚未写回工作区的内容，会出现 **Unpublished content** 提示：

- **Restore the unpublished content**（恢复尚未写回的内容）：先把保留内容恢复到工作区文件，再打开编辑器。
- **Start from the current file**（从当前文件开始）：使用工作区现在的文件打开编辑器；保留的版本仍在历史记录中，不会被删除。
- 「关闭」（Close）：暂不选择，也不打开编辑器。

恢复失败时提示会保留，并显示错误；不要把失败当作恢复成功。如果显示 **Expired**（会话过期），可用 **Open again**（重新打开）重新进入上述检查。若上次关闭留下待处理冲突，会先显示冲突选择。

## 文件被 Agent 或其他操作改动时

工作区文件是你与 Agent 共用的文件。编辑期间出现 **Workspace file changed** 提醒，表示工作区中的文件已发生变化，不代表你的编辑已经丢失。

保存遇到冲突时，你的内容会先保留为一个版本，再显示 **Resolve conflict**：

| 选择                                           | 结果                                                                                                                           |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Save as new file**（另存为新文件，默认选项） | 把你的内容写入一个新文件，不覆盖当前工作区文件。原目录不可用时，新文件放在工作区根目录。                                       |
| **Overwrite workspace file**（覆盖工作区文件） | 需再点 **Confirm overwrite** 确认。当前工作区内容先保留为历史版本，然后用你的内容替换。**Cancel overwrite** 取消这次覆盖确认。 |

原文件已经不存在时，只提供 **Save as new file**，不会按旧路径复活文件。关闭冲突对话框不等于解决冲突，也不会丢弃已保留的内容。

如果冲突发生在离开编辑器之后：原文件还在但内容已变，留到下次打开处理；原文件已被删除，系统会尝试自动另存为新文件，并在结果提示中给出文件名。若整个工作区文件目录已不存在，无法另存；界面会提示失败，内容仍保留在版本记录中。

## 历史版本与附件的区别

- **Version history**（版本历史）可查看保留版本。要恢复旧内容，先关闭该文档的编辑器，再选择版本的 **Restore**（恢复）；恢复会形成新版本，不抹掉已有历史。
- Office 编辑修改的是**工作区文件**，不会回写 WebUI 当初存储的聊天附件，也不会更新已经发给模型的文件内容。需要 Agent 使用修改结果时，先确认状态栏「已保存」，再明确让它重新读取工作区文件；不能假定模型已有上下文随之更新。
